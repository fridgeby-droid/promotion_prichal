# «Причал»: Bothost, Excel и JSON

## Запуск
1. Загрузите ZIP на bothost.ru. Файлы bot.py и requirements.txt расположены в корне архива.
2. Выберите собственный Dockerfile (Python 3.12, запуск python bot.py). При автоматической сборке укажите главный файл bot.py и Python 3.12.
3. В панели переменных окружения заполните BOT_TOKEN, ADMIN_IDS (числовые Telegram ID через запятую), DATA_DIR=/app/data и URL из .env.example. Сам .env читается только Docker Compose, на Bothost используйте переменные панели.
4. Включите постоянное хранилище /app/data с правом записи. Запускайте одну копию. Документация: https://bothost.ru/docs/database-storage и https://bothost.ru/docs/main-file-entrypoint .
5. Отправьте /start и /admin с разрешенного аккаунта, затем Excel документом в личный чат с ботом.

Локально: скопируйте .env.example в .env, заполните и выполните docker compose up -d --build.

## Excel
Поддерживается .xlsx до 5 МБ, 50 000 строк. Первый лист, столбец A, со второй строки. Заголовок и остальные столбцы игнорируются; пустые ячейки пропускаются. Код — ровно 8 латинских букв или цифр, регистр сохраняется. Ячейки должны быть текстовыми, особенно при ведущих нулях. Формулы, числовые ячейки, пробелы, кириллица и неверная длина отклоняют весь файл без частичного импорта. .xls предварительно пересохраните в .xlsx.
Повторная загрузка только дополняет запас. Дубликаты, включая выданные коды, пропускаются. /admin показывает запас, выданные коды и остаток.

## Выдача и QR
Один Telegram ID получает один код в этой акции. Код сохраняется до отправки изображения; при повторном запросе или сбое возвращается тот же. Разные пользователи получают разные коды. QR содержит непосредственно восемь символов из таблицы, без ссылки. Погашения, отзыва и перевыпуска нет. Если запас пуст, бот предлагает зайти позже.
Входной QR на кассе отдельно ведет на https://t.me/ИМЯ_БОТА?start=store_01 . Источник первого входа сохраняется.

## Меню и таймеры
Семь пунктов меню сохранены по схеме 16 ноября 2026. URL задаются через SBIS_URL, CHANNEL_URL, ADDRESSES_URL, CARD_POST_URL, RAFFLE_POST_URL, SUPPORT_URL. Пустой или некорректный HTTPS URL показывает сообщение о временном отсутствии ссылки. Переход СБИС не подтверждает регистрацию. Доставка и заказы не реализованы.
После первого успешного показа QR — 120 секунд, карты — 180 секунд. Повторное открытие не переносит срок. Общая отметка для обоих таймеров и ручного розыгрыша. Пункты 3–7 не создают заданий. Задания переживают рестарт. Повторное ручное открытие розыгрыша показывает его экран.
Перед отправкой приглашения сохраняется sending, после успеха sent. При неопределенной сетевой ошибке либо рестарте во время отправки — uncertain, без автоматического повтора. Такие случаи требуют ручной проверки. Telegram не предоставляет idempotency key: гарантировать одновременно отсутствие дублей и доставку при любом сбое нельзя. Короткий сбой после показа экрана до записи таймера может потребовать повторного открытия экрана. Обычные ответы при аварии до сохранения update_id могут повториться, код остается прежним.

## Данные
/app/data/state.json хранит пользователей, источники входа, коды и назначения, события, задания, приглашения и последние 10 000 update_id. Запись через временный файл, fsync и атомарную замену. Файловая блокировка запрещает две копии с одной папкой. Поврежденный JSON останавливает запуск, а не сбрасывает выдачи.
Это MVP для небольшой нагрузки: весь JSON переписывается, история событий увеличивает его размер. Резервную копию state.json сохраняйте при остановленном боте. Не удаляйте состояние и не заменяйте старой копией: потеряется история выдач. Не запускайте копии с независимыми папками. Не используйте docker compose down -v. Новый Excel не начинает новую акцию. Автоматической миграции из старого PostgreSQL-выпуска нет.

## Проверки
python -m unittest -v test_storage.py
python -m compileall -q .
Проверяются сохранение назначения после рестарта, уникальная выдача, пустой запас, повторный импорт, отказ ошибочного импорта, чтение Excel, сохранение задания и uncertain. Полный запуск Telegram и таймеры на Bothost проверьте с действующим BOT_TOKEN перед акцией.

## Единое меню
Все переходы меню, показ QR и возврат обновляют одно сообщение с изображением и кнопками. Номер сообщения сохраняется в JSON, повторный /start также обновляет его. В разделах отображается баннер PRICHAL, в подарке — персональный QR. Если пользователь удалил сообщение, бот создаст новое. Старые сообщения предыдущего выпуска автоматически не удаляются. Отложенное приглашение остается отдельным уведомлением; его кнопка возврата открывает сохраненное меню. Ответы администратору также отдельные.

### Исправление single-menu-2
При нажатии кнопки редактируется именно сообщение, на котором нажата кнопка, даже если в JSON сохранен другой номер. Ошибка редактирования при переходе не вызывает отправку нового сообщения. /start может восстановить удаленное меню. Возврат из отдельного уведомления теперь превращает само уведомление в экран меню. Старые сообщения автоматически не удаляются.
После загрузки нового архива выполните пересборку/деплой на Bothost, затем /admin: ответ должен содержать «Версия: single-menu-2». Если строки нет, работает предыдущий выпуск. Папку data не заменяйте. Проверки: python -m unittest -v test_menu.py test_storage.py (Telegram API заменен тестовым транспортом).

## Админ-панель admin-panel-1
Открывается командой /admin только для ADMIN_IDS. Существующий state.json обновляется без потери выдач. Не заменяйте data при обновлении.
- Выдача включается и выключается; уже выданные коды доступны всегда. Текст паузы редактируется.
- Excel дополняет запас. Удаление свободных кодов: вся загрузка, все свободные или выборочные коды; требуется подтверждение. Выданные записи сохраняются. Для старых загрузок без номера партии доступны выборочное удаление и удаление всех свободных.
- Статистика: все пользователи, получатели, события, источники входа и даты; счетчики новых пользователей за сутки/неделю. Excel хранит идентификаторы и потенциально опасные формулы как текст. Времена в выгрузке — UTC Unix timestamp.
- Тексты, названия кнопок, ссылки, изображения меняются через выбор элемента, ввод, предпросмотр и сохранение. Настройки действуют при следующем открытии раздела. Отмена последнего изменения возвращает предыдущий снимок настроек, но не отменяет выдачу/импорт/удаление кодов. Черновики индивидуальны для админа и сбрасываются при рестарте.
- Изображения хранятся как Telegram file_id. В подарке изображение располагается над QR. «Наш канал» остается прямой URL-кнопкой без промежуточного экрана, поэтому картинка этого пункта не отображается.
- Таймеры можно выключить; задания остаются. При включении можно сохранить задания (просроченные выполнятся) или отменить старые без повторного запуска по тем же веткам. Новые задержки действуют только на новые задания. Тексты приглашения находятся в разделе текстов.
- Порог остатка настраивается. Уведомление всем ADMIN_IDS отправляется однократно при достижении порога и повторяется после пополнения выше порога. Администратор должен сначала открыть личный чат с ботом.
- Резервная копия содержит полный JSON, включая назначения, настройки и журнал. Скачивается администратору в личный чат. Восстанавливать вручную при остановленном боте; старая копия теряет более поздние выдачи. Изображения file_id доступны тому же боту.
- Журнал скачивается в Excel. Сохраняются изменения настроек, удаление, импорт, выгрузки и отмена. Регистрация в СБИС и URL-клики не считаются подтвержденными событиями.
Проверка сборки: /admin показывает admin-panel-1. Тесты: python -m unittest -v test_storage.py test_menu.py test_admin.py. Проверка реального Telegram и Bothost требует действующего токена и деплоя.

### Единое сообщение администратора — admin-panel-2
Разделы админ-панели, подсказки ввода, ошибки проверки, предпросмотр текста/фото, подтверждения и результаты импорта обновляют одно сообщение. Его ID хранится в admin_screens отдельно от клиентского меню. /admin повторно открывает сохраненное сообщение. Кнопки редактируют сообщение, на котором нажаты; ошибки редактирования не создают дубль. Если сообщение удалено, /admin создаст новое. Сообщения, отправленные самим администратором, остаются в чате. Выгрузки Excel, JSON-копии и уведомления об остатке отправляются отдельно. Старые сообщения предыдущих версий не удаляются.

### Исправление /start — admin-panel-3
/start сбрасывает незавершенное редактирование администратора и переключает сообщение админ-панели на клиентское меню. /admin переключает его обратно. ID экрана администратора синхронизируются; новые сообщения для переключения не создаются. После удаления экрана команда может восстановить его. Проверка включает настоящую маршрутизацию aiogram для /admin → ввод → /start → /admin; Telegram API заменен тестовым транспортом.

### Актуальное поведение — menu-flow-1
Эта версия заменяет прежнее правило неизменного сообщения. Переходы inline-кнопками обновляют меню на месте. /start, /admin и постоянные кнопки под полем ввода показывают новое меню внизу и снимают кнопки с предыдущего. Ответ администратора текстом, фото или Excel также переносит панель вниз. Сообщения самого администратора сохраняются. Навигационная клавиатура устанавливается при первом вызове команды в этой версии. Файлы и уведомления остаются отдельными сообщениями. Механика нескольких акций НЕ добавлена: один код на пользователя за весь срок хранения текущего состояния; новый Excel не сбрасывает выдачи. Не удаляйте state.json для запуска новой акции.

## Акции — campaigns-1 (актуальная механика)
Предыдущие указания «один код за весь срок» заменены правилом «один код на Telegram ID в каждой акции».
При первом запуске после обновления существующие данные становятся «Первой акцией (перенесена)». Никакие выдачи при обновлении не сбрасываются. Перед обновлением скачайте резервную копию, data не заменяйте.
/admin → «Акции: новая / завершить / архив» → «Создать новую акцию» → название → подтверждение. Старая акция автоматически завершается и архивируется: запас, назначения, пользователи на момент завершения, таймеры, приглашения, загрузки и настройки. Глобальный журнал событий сохраняется. Новая акция имеет пустой запас, выключенную выдачу и выключенные автоматические приглашения. Загрузите Excel новой акции, проверьте тексты и ссылки, включите выдачу; при необходимости отдельно включите приглашения. Новые таймеры запускаются только после открытия соответствующих разделов пользователями.
Если новый Excel был загружен ДО создания новой акции, он относится к прежней: после создания новой загрузите его снова. Коды, которые уже были выданы в прошлых акциях, при импорте пропускаются; используйте действительно новые коды.
«Завершить текущую» прекращает новые выдачи и автоматические приглашения; уже выданный код остается доступен до создания следующей акции. Статистика и список получателей обычного отчета относятся к текущим назначениям; общая база пользователей сохраняется. «История всех выдач (Excel)» включает все акции, ID пользователя, код и дату выдачи, а также список акций. Архив входит в JSON-резервную копию.
Старые картинки QR, уже отправленные в Telegram, сами не исчезают и не аннулируются: бот не управляет погашением. При новом открытии раздела подарка покупатель получает код активной акции. Срок действия старых кодов нужно завершать в системе, где они применяются.
Нельзя вернуть старую версию бота после перехода на акции без согласованного восстановления данных. Полные копии архива увеличивают JSON; решение рассчитано на небольшой MVP.
