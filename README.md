# «Причал»: Bothost, Excel и JSON

## Запуск
1. Загрузите ZIP на bothost.ru. Файлы bot.py и requirements.txt расположены в корне архива.
2. Выберите собственный Dockerfile (Python 3.12, запуск python bot.py). При автоматической сборке укажите главный файл bot.py и Python 3.12.
3. В панели переменных окружения заполните BOT_TOKEN, ADMIN_IDS (числовые Telegram ID через запятую), DATA_DIR=/app/data и URL из .env.example. Сам .env читается только Docker Compose, на Bothost используйте переменные панели.
4. Включите постоянное хранилище /app/data с правом записи. Запускайте одну копию. Документация: https://bothost.ru/docs/database-storage и https://bothost.ru/docs/main-file-entrypoint .
5. Отправьте /start и /admin с разрешенного аккаунта, затем Excel документом в личный чат с ботом.

Локально: скопируйте .env.example в .env, заполните и выполните docker compose up -d --build.

## Excel
Поддерживается .xlsx до 5 МБ, 50 000 строк. Первый лист, столбец A, со второй строки. Заголовок и остальные столбцы игнорируются; пустые ячейки пропускаются. Код — ровно 8 латинских букв или цифр, регистр сохраняется. Ячейки должны быть текстовыми, особенно при ведущих нулях. Формулы, числовые ячейки, пробелы, кириллица и неверная длина отклоняют весь файл без частичного импорта. .xls предварительно пересохраните в .xlsx.
Повторная загрузка только дополняет запас. Дубликаты, включая выданные коды, пропускаются. /admin показывает запас, выданные коды и остаток.

## Выдача и QR
Один Telegram ID получает один код в этой акции. Код сохраняется до отправки изображения; при повторном запросе или сбое возвращается тот же. Разные пользователи получают разные коды. QR содержит непосредственно восемь символов из таблицы, без ссылки. Погашения, отзыва и перевыпуска нет. Если запас пуст, бот предлагает зайти позже.
Входной QR на кассе отдельно ведет на https://t.me/ИМЯ_БОТА?start=store_01 . Источник первого входа сохраняется.

## Меню и таймеры
Семь пунктов меню сохранены по схеме 16 ноября 2026. URL задаются через SBIS_URL, CHANNEL_URL, ADDRESSES_URL, CARD_POST_URL, RAFFLE_POST_URL, SUPPORT_URL. Пустой или некорректный HTTPS URL показывает сообщение о временном отсутствии ссылки. Переход СБИС не подтверждает регистрацию. Доставка и заказы не реализованы.
После первого успешного показа QR — 120 секунд, карты — 180 секунд. Повторное открытие не переносит срок. Общая отметка для обоих таймеров и ручного розыгрыша. Пункты 3–7 не создают заданий. Задания переживают рестарт. Повторное ручное открытие розыгрыша показывает его экран.
Перед отправкой приглашения сохраняется sending, после успеха sent. При неопределенной сетевой ошибке либо рестарте во время отправки — uncertain, без автоматического повтора. Такие случаи требуют ручной проверки. Telegram не предоставляет idempotency key: гарантировать одновременно отсутствие дублей и доставку при любом сбое нельзя. Короткий сбой после показа экрана до записи таймера может потребовать повторного открытия экрана. Обычные ответы при аварии до сохранения update_id могут повториться, код остается прежним.

## Данные
/app/data/state.json хранит пользователей, источники входа, коды и назначения, события, задания, приглашения и последние 10 000 update_id. Запись через временный файл, fsync и атомарную замену. Файловая блокировка запрещает две копии с одной папкой. Поврежденный JSON останавливает запуск, а не сбрасывает выдачи.
Это MVP для небольшой нагрузки: весь JSON переписывается, история событий увеличивает его размер. Резервную копию state.json сохраняйте при остановленном боте. Не удаляйте состояние и не заменяйте старой копией: потеряется история выдач. Не запускайте копии с независимыми папками. Не используйте docker compose down -v. Новый Excel не начинает новую акцию. Автоматической миграции из старого PostgreSQL-выпуска нет.

## Проверки
python -m unittest -v test_storage.py
python -m compileall -q .
Проверяются сохранение назначения после рестарта, уникальная выдача, пустой запас, повторный импорт, отказ ошибочного импорта, чтение Excel, сохранение задания и uncertain. Полный запуск Telegram и таймеры на Bothost проверьте с действующим BOT_TOKEN перед акцией.

## Единое меню
Все переходы меню, показ QR и возврат обновляют одно сообщение с изображением и кнопками. Номер сообщения сохраняется в JSON, повторный /start также обновляет его. В разделах отображается баннер PRICHAL, в подарке — персональный QR. Если пользователь удалил сообщение, бот создаст новое. Старые сообщения предыдущего выпуска автоматически не удаляются. Отложенное приглашение остается отдельным уведомлением; его кнопка возврата открывает сохраненное меню. Ответы администратору также отдельные.
